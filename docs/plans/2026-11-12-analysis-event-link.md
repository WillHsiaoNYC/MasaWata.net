## Agreed scope and justified implementation defaults

The following defaults implement the requested deep-link support without new feature UI or a general navigation redesign. They are planning defaults, not earlier explicit user design approvals; stop for clarification only if source evidence makes one infeasible without a material behavior change.

1. Canonical URL: `https://masawata.net/CarPlateScan/event/analysis-collections/`. Accept the no-trailing-slash form too. Ignore benign query/fragment for routing, so locale overrides cannot inject app actions. Keep strict host/scheme/credential/port/exact-path validation; reject encoded-path aliases, extra segments, wrong case/path, custom schemes, unknown events and deceptive hosts.
2. Add a distinct Analysis event case. When safe, open the existing **Analysis home** directly, with its existing letters/digits, starting/ending and length choices. Do not show the Everyday Collection screen, auto-select a collection/capture, alter the selector, start scanning, or synthesize saved records. No new event-specific native landing screen is planned.
3. Route through the existing welcome/replay deferral. While first-run onboarding is visible, do not attach normal app content behind it; deliver once after Finish or Skip. During Settings welcome replay, wait for actual cover dismissal, then route. Use one authoritative latest undelivered supported-event intent across welcome and later deferral, scoped to the receiving scene. A newer accepted event supersedes an older pending event; rejected URLs leave the pending intent intact. Already-presented events are acknowledged, not pending. Keep current Everyday presentation eligibility above modals; do not newly apply Analysis-only busy gates to the existing event. Use two-phase delivery: when the receiving scene is active/idle, still owns the intent and passes protected-work gates, it may safely select the Analysis tab even before its view/store attaches. Retain the home-reset request token through loading; acknowledge consumption only after the attached destination applies that token. Never wait for Analysis attachment before selecting the tab that creates it. Scene-active and actual attachment changes are real release signals; scene ownership teardown cancels the intent.
4. Preserve protected work. If a review/editor, import/photo picker, Auto Review, purchase sheet, existing event sheet, or other user-owned modal is open, leave it in place. If Scan is starting/running/stopping/importing/processing, do not switch tabs and trigger onDisappear cleanup solely for this link. Retain the current authoritative undelivered intent and deliver after the user finishes/dismisses the protected work and the relevant screen is safely idle. Also gate pushed saved-capture inline state: `inlineReadingDraft`, `hasReadingChanges`, `isCommittingReading`, `model.isReviewing`, `model.isUpdating`, `model.isPreparingCloudCrop`, `browser.isSelecting`, browser/crop/annotation editor and confirmation ownership. Do not force-save, auto-discard or bypass the existing Back/discard guard. Observe the actual state owners with narrow scene-owned callbacks/admission state; a root UIViewController check or Scan busy flag alone is insufficient. Do not add persistence, a polling timer or a general navigation framework. Preserve existing scene/background policy, including scanner shutdown or saved-detail cloud-review revocation when the external probe foregrounds. A subsequent explicit independent destination choice (tab, new record/collection, new Start Scan/photo import/shortcut journey, or Settings event action) cancels/supersedes it **before** busy-to-idle/dismissal callbacks can deliver a stale intent. A Stop that merely completes the existing scan is distinct from starting a new scanner journey. Do not infer user intent from every programmatic selection change; retain clear origins for explicit navigation vs completion. Cancel pending state on owning scene teardown, and acknowledge consumption once so no later callback replays it.
6. Storage opening/error follows the existing Analysis loading/error UI. Link receipt itself performs no store reads/writes and cannot claim an empty authoritative library. Existing model/data-readiness checks remain the callee's authority before reads/derived work. No persistence schema, caching-window, migration, scan acceptance or cloud behavior change is intended.
